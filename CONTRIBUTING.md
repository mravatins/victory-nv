# Contributing to victory-nv

Thanks for helping. Issues, measurements, fixes and docs are all welcome.

## Ground rules

1. **No proprietary material, ever.** No executables, assets, shader dumps,
   decompiled code, screenshots of a title's content, or tables extracted from
   one. Read [docs/asset-policy.md](docs/asset-policy.md). Run
   `cargo xtask install-hooks` once; the pre-commit hook and CI run
   `cargo xtask policy`.
2. **Keep it a platform.** Code belongs to the emulator (formats, runtime
   services, GPU translation). Per-title workarounds must be clearly marked
   (`shortcut:` comments) and switchable.
3. **License.** By contributing you agree that your contribution is licensed
   under GPL-3.0-or-later, the license of this repository. Only submit code you
   wrote or code under a compatible license, with its origin credited in the
   commit message and in [CREDITS.md](CREDITS.md).

## Workflow

```powershell
cargo xtask install-hooks
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
```

CI runs the same commands on Windows. Tests must not need title data. Use
synthetic data generated by our own code, and WARP for GPU tests.

- Branch from `main` and keep each pull request to one topic.
- New behaviour that is risky or experimental goes behind a `VICTORY_*`
  environment switch, off by default, documented in a comment where it is
  read.
- Commit messages: a short imperative subject with an area prefix (`GPU:`,
  `Shaders:`, `HLE:`, `Relay:`, `Diagnostics:`), then the why in the body.

## Performance changes

Include numbers. Use the automated benchmark:

```powershell
.\scripts\bench\run.ps1 -Exe <title exe> -Target target-a -Log before.log -AutoStart
.\scripts\bench\run.ps1 -Exe <title exe> -Target target-b -Log after.log  -AutoStart
.\scripts\bench\measure.ps1 -Log after.log -BaselineLog before.log -Survey
```

Paste the JSON output, your GPU, CPU and driver version into the pull request.
Report both frame time and total submission wait, because work can move
between wait categories without the frame getting faster. The current state and
open bottlenecks are in [docs/nvidia-performance.md](docs/nvidia-performance.md).
Pick one from there if you want somewhere to start.

## Reporting bugs

Use the issue templates. Attach `crashes.log`, the relevant log lines
(`VICTORY_LOG=info`) and your hardware. Do not attach anything covered by the
asset policy.
